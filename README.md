# 한울 2026 축제 독자 피드백

감나무 열매·잎색과 아이보리를 사용한 한울 신문 부스 웹 앱입니다. 첨부된 감 로고를 기반으로 투명 배경 이미지를 만들고 WebP로 최적화했습니다. 기사 원문이나 API 키는 저장소에 넣지 않습니다.

## 실행

Node.js **24.5 이상**이 필요합니다. 외부 npm 패키지, 빌드, CDN 없이 실행됩니다.

```sh
cd /workspace/sungnamhigh_hanul
if [ ! -e .env ]; then cp .env.example .env; fi
chmod 600 .env
```

`.env`에 다음을 설정합니다. `.env`는 Git 및 배포용 ZIP에서 제외됩니다.

| 이름 | 설정 |
| --- | --- |
| `PADLET_API_KEY` | 전달한 패들렛 API 키. 서버에서만 사용합니다. |
| `ADMIN_PASSWORD` | 기본값 `ADMIN`. 관리자 인증은 서버에서 처리합니다. |
| `SHEETS_URL` | Apps Script 웹 앱의 `/exec` URL. 기존 URL이 예시 파일에 들어 있습니다. |
| `SHEETS_TOKEN` | 서버와 Apps Script 사이의 임의의 공유 비밀 문자열. 아래 스크립트 속성과 같은 값으로 설정합니다. |
| `DATA_DIR` | 게시 설정을 보관하는 영속 디렉터리. 기본값 `./data`. |
| `HOST`, `PORT` | 기본값 `127.0.0.1`, `8000`. 외부 서버에서는 `HOST=0.0.0.0`과 호스팅 서비스가 지정한 포트를 사용합니다. |
| `TRUST_PROXY` | 신뢰하는 HTTPS 프록시 뒤에서만 `true`. HTTPS 전달 정보를 이용해 쿠키에 `Secure`를 설정합니다. |

공유 비밀 문자열은 로컬에서 `openssl rand -hex 32` 등으로 생성할 수 있습니다. 파일이나 채팅으로 공개하지 않고 서버 환경 변수와 Apps Script 속성에 각각 입력합니다.

```sh
npm start
```

로컬 브라우저에서 포트 8000의 앱을 엽니다. **Node 서버가 필요한 앱**이므로 HTML 파일을 직접 열거나 정적 GitHub Pages에만 올리면 관리자·패들렛·시트 API는 동작하지 않습니다. 외부 배포에는 Node 호스팅과 HTTPS를 사용하고, `DATA_DIR`를 영속 볼륨에 보관합니다. 한 데이터 디렉터리에는 Node 프로세스 하나를 사용합니다. 서버를 재시작해도 게시된 기사 선택은 유지되고, 관리자 세션은 종료됩니다.

## 기존 Apps Script 교체

1. 사용자가 제공한 [Apps Script 프로젝트](https://script.google.com/u/0/home/projects/1iBfLlpOIyr2QXDhnFdGpW_jTIqcnuvN7dgKHGEystITugw9ud1od9ryn/edit)의 기존 코드를 [`Code.gs`](Code.gs)로 교체합니다. 같은 프로젝트의 다른 파일에 기존 `doGet`, `doPost`가 남아 있으면 삭제하거나 이름을 바꿔 중복 정의를 없앱니다.
2. **프로젝트 설정 → 스크립트 속성**에 `HANUL_WEBHOOK_SECRET`을 추가하고 서버의 `SHEETS_TOKEN`과 같은 값을 입력합니다. API 키는 이 속성에 넣지 않습니다. 패들렛 키는 Node 서버에서만 사용합니다.
3. **배포 → 배포 관리 → 기존 웹 앱 수정 → 새 버전 → 배포**를 선택합니다. 실행 사용자는 **나**, 액세스 권한은 **모든 사용자**로 설정하고 필요한 스프레드시트 권한을 승인합니다. 기존 배포를 업데이트하면 `/exec` URL을 그대로 사용할 수 있습니다. 새 배포를 만들었다면 `.env`의 `SHEETS_URL`도 바꿉니다.
4. 스프레드시트 첫 번째 탭에서 **G~I열이 비어 있는지** 확인합니다. 기존 A~F열과 응답은 보존합니다. G~I열에 이미 다른 데이터가 있으면 덮어쓰지 않고 저장을 중단합니다. 이 경우 해당 열을 별도 위치로 옮긴 뒤 다시 시도합니다.
5. 배포 URL에 `?action=dashboard`를 붙여 읽기 요청을 하면 `success: true`와 `dashboard` 집계가 반환되어야 합니다. 기본 URL의 `status: online`은 코드가 실행 중임만 의미하며 집계 검증을 대신하지 않습니다.

| 열 | 내용 |
| --- | --- |
| A~F | 기존 순서 유지: 제출 시간, 소속, 성별, 기사 제목, 별점, 한 줄 평 |
| G | 서버가 발급하고 시트가 확인한 제출 확인 번호 |
| H | UUID 중복 방지 번호. 재시도나 서버 재시작 후 중복 기록 방지 |
| I | 패들렛 기사 ID |

기존 Apps Script는 수집만 지원하고 집계 조회와 저장 확인 번호를 반환하지 않습니다. **교체 후 새 버전 배포가 필요합니다.** 새 서버는 저장 확인을 받기 전에는 완료 화면을 보여주지 않습니다. 과거 A~F열 데이터도 집계하며, 빈 행이나 소속·제목·평점이 올바르지 않은 행은 집계에서 제외합니다. 개별 소감·성별·응답 목록은 공개 대시보드 API로 전달하지 않습니다.

## 패들렛 기사 선택

1. 페이지 우측 상단 **톱니바퀴**를 누릅니다.
2. 비밀번호 **ADMIN**으로 로그인합니다 (`ADMIN_PASSWORD`를 바꿨다면 변경한 비밀번호 사용).
3. **‘2026 한울’ 패들렛의 전체 URL 또는 API ID**를 입력합니다. API ID는 패들렛 우측 상단 **⋯ → Developer info**에서 확인합니다. 키를 발급한 계정에 해당 보드의 API 읽기 권한이 있어야 합니다.
4. **섹션과 기사 불러오기**를 누르고, 섹션 전체나 개별 기사를 선택합니다. **게시하기**를 누르면 모든 방문자에게 같은 기사 목록이 표시됩니다. 선택 0개를 게시하면 목록을 비웁니다.
5. 패들렛에서 내용을 수정한 경우 60초 후 목록을 다시 불러와 재게시합니다. 방문자 페이지는 게시된 스냅샷을 읽으므로 방문자마다 패들렛 API를 호출하지 않습니다.

보드 주소와 게시할 기사는 운영자가 결정하도록 초기 목록을 비워 두었습니다. 예제 기사와 예제 응답은 사용자 화면에 없습니다. 패들렛 HTML은 실행하지 않고 텍스트로 표시하며, 첨부 파일은 제공된 패들렛 원문 링크로 확인합니다.

## 동시 접속과 오류 처리

- CSS·JavaScript·로고를 앱 서버에서 제공합니다. 외부 Tailwind·Chart.js·아이콘·폰트 CDN을 제거했고, 로고는 약 63 KB WebP입니다.
- 방문자는 게시된 기사 스냅샷만 읽습니다. 관리자 보드 조회는 60초 공유 캐시를 사용하며 페이지네이션을 끝까지 읽어야 게시할 수 있습니다.
- 대시보드는 서버에서 20초 동안 조회 결과와 진행 중인 요청을 공유합니다. Apps Script에도 20초 캐시와 잠금을 적용합니다. 숨겨진 탭은 자동 갱신을 멈춥니다.
- 제출은 약 80ms 동안 모아 최대 50건씩 시트에 기록합니다. Apps Script는 잠금 안에서 중복 번호를 확인하고 `setValues` 한 번으로 여러 행을 기록합니다.
- UUID를 같은 요청의 재시도에 재사용하고, 확인된 응답에만 상품 확인 번호를 표시합니다. 시트에 저장되지 않은 응답을 로컬 집계에 더하지 않습니다.
- 시트 조회 실패 시 마지막으로 확인한 시트 집계만 최대 5분간 오류 안내와 함께 표시합니다. 이전 집계가 없으면 숫자를 꾸며 표시하지 않습니다.
- 잘못된 입력·과도한 요청·인증 실패·외부 API 시간 초과를 처리합니다. 패들렛 키, 공유 비밀, 서버 파일과 영속 설정은 공개 경로로 제공하지 않습니다.

## 검증

```sh
npm test
```

자동 테스트는 Node 내장 러너와 모의 외부 API/시트를 사용합니다. 60건 동시 대시보드 조회의 공유 요청, 40건 동시 제출의 묶음 저장·중복 방지, 저장 실패 시 완료 화면 차단, HTML 정리, 패들렛 페이지네이션, 인증·파일 접근 제한, 기존 6열 시트와 Apps Script 호환성을 검사합니다. 로컬 테스트 수치는 실제 패들렛·Google 서비스의 응답 속도나 운영 서버 최대 접속 수를 보증하지 않습니다.

브라우저에서는 관리자 로그인 → 섹션/기사 선택 → 게시 → 기사 평가 → 제출 확인 → 시트 집계 대시보드의 흐름과 모바일 레이아웃을 검증했습니다. 이 검증에도 모의 외부 서비스를 사용했습니다. 실행 환경에서 실제 패들렛·Google 접속은 네트워크 정책의 HTTP 403 때문에 검증하지 못했습니다. 실제 운영 전에는 새 Apps Script를 배포하고 키·공유 비밀을 설정한 뒤 실제 기사 1개와 응답 1건으로 확인합니다.

필요한 서버 외부 접속 호스트는 `api.padlet.dev`, `script.google.com`, `script.googleusercontent.com`입니다. 환경 설정 초안에는 이 호스트들과 API 문서·GitHub 검증용 호스트를 추가했습니다. 초안 저장만으로 현재 실행 환경의 네트워크 정책이 바뀌지는 않습니다.
